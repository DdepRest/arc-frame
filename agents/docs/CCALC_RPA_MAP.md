# CCalc 9.12 (Deceuninck) — карта RPA-управления

Документ описывает, как `tools/pvc_bridge/ccalc_bot.py` управляет окном CCalc
и как каждый шаг проверяется. Все координаты — в системе окна TForm1
(`click_rel`), если не указано «экранные». Окно развёрнуто на весь экран,
rect `(-8,-8,1928,1048)`; `click_rel(x,y)` кликает в `(x-8, y-8)`.

## Порядок построения окна 1060×1340

1. Рама протяжкой по диагонали.
2. Импост вертикальный по центру (530/530).
3. Створка: протяжка **сверху-справа вниз-влево** (задаёт петли справа).
   Одиночный клик по створке ставит москитную сетку — поэтому после построения
   створки бот **не** кликает по ней (`_skip_net`): сетка в конструкцию CCalc не
   ставится, она уходит отдельной позицией в заказ A.R.C. Frame. Прежнее
   поведение возвращает `--with-net`.
   Размер сетки считается от проёма: ширина −85 мм, высота −105 мм
   (`NET_WIDTH_OFFSET`/`NET_HEIGHT_OFFSET`), окно 1060×1340 → сетка 445×1235;
   переопределяется через `--net-width/--net-height`.
4. Ручка HOPPE + стеклопакет CПД-32: инструмент и клик по створке.
5. Фурнитура VORNE: инструмент и клик по створке.
6. Дополнительные элементы (анкерные пластины + подоконник): вызов `TDobElemDlg` через кнопку `TOOL_EXTRA`.

## Автопроверки

| Шаг | Проверка |
| --- | --- |
| Рама | отношение сторон рамки на снимке чертежа (`534x677 px, 0.789` при ожидаемых 0.791) |
| Импост | ширина секций в мм и смещение импоста в % (`530 мм, +0.0 %`) |
| Створка | распределение тёмных пикселей слева/справа внутри рамки |
| Ручка + стеклопакет | «Стоимость» в «Листе заказа» выросла после пересчёта (10094 → 12885 ₽) |
| Фурнитура | «Стоимость» выросла после пересчёта (12885 → 16122 ₽) |
| Доп. элементы (анкерные пластины + подоконник) | «Стоимость» в «Листе заказа» выросла после добавления каждого элемента и пересчёта |
| Скидка | «Стоимость со скидкой» / «Стоимость» = 1 − скидка/100 (0.800 при 20 %) |

## Установочные и дополнительные элементы (TDobElemDlg)

Добавление комплектующих (анкерных пластин и подоконников) выполняется через диалог «Установочные и дополнительные элементы»:

1. Клик по кнопке `TOOL_EXTRA` `(127, 263)` на вкладке «Чертёж» открывает окно `TDobElemDlg`.
2. **Критически важный шаг**: Одиночный клик по строке конструкции в верхнем `TListView` по координатам `(62, 102)` для явного выделения конструкции. Без этого клика тулбар `TToolBar` не привязан к конструкции, и нажатие кнопки «+» не открывает список элементов.
3. **Выбор пункта в каталоге `TListElemDlg`** (общий для всех элементов):
   - Клик по первой кнопке «+» на панели `TToolBar` `(27, 54)` → открывается каталог `TListElemDlg`.
   - Пункт ищется в `TListBox` по нормализованному тексту (для подоконника — фильтр по ширине: «Подоконник ПВХ 350 мм» предпочтительнее «LUX/глянец»).
   - Список прокручивается `LB_SETTOPINDEX(idx - 2)`, клик — по `(bx + 40, by + 10 + (idx - top) * 19)`: **высота строки ListBox — 19 px**. Считать её как «высота списка / число пунктов» нельзя — список длинный (189 пунктов) и клик уезжает в чужую строку.
   - После клика обязательна проверка `LB_GETCURSEL == idx`, иначе шаг падает с понятной ошибкой.
   - Подтверждение — кнопка «ОК» (`fallback_rel=(496, 10)`), а не двойной клик: двойной клик каталог не закрывает. Затем проверяется, что `TListElemDlg` исчез.
4. **Открытие «Редактора» (`TDobElemEditDlg`)** — самое хрупкое место:
   - После «ОК» хэндл `TDobElemDlg` перечитывается: окно может быть пересоздано, старый `TListView` показывает неверное число строк.
   - Число строк — `LVM_GETITEMCOUNT (0x1004)`; клик — по последней строке `(lx + 120, ly + 25 + (rows - 1) * 19)`.
   - Клик должен быть **настоящим быстрым двойным** (два `mouse_event` LEFTDOWN/LEFTUP с интервалом < 300 мс). Два раздельных клика через `SetCursorPos` + пауза Delphi читает как два одиночных: строка выделяется, но «Редактор» не открывается — именно из-за этого шаг раньше «не открывался» три раза подряд.
   - Запасной вариант — `WM_KEYDOWN/VK_RETURN` в `TListView` по выделенной строке.
5. **Значения в «Редакторе»:** в окне один `TEdit` — «Размер» (количество для пластин, длина для подоконника), поля «Цвет» — комбобокс. Записывается одно значение, читается обратно и сверяется; затем «ОК» (`fallback_rel=(272, 50)`) и проверка, что окно закрылось.
6. **Завершение**:
   - Закрытие диалога `TDobElemDlg` сообщением `WM_CLOSE`.
   - Контроль пересчёта стоимости: переход в «Лист заказа» `(93, 61)` → клик «Пересчёт» `(107, 100)` → верификация дельты стоимости (`cost_after > cost_before`).

## Лист заказа

Поля адресуются **якорем** — смещением (dx, dy) от левого верхнего угла окна,
а не номером строки: у строк «Стоимость» и «Стоимость со скидкой» первая
колонка пустая, из-за чего нумерация полей съезжала и значение уезжало в
чужой контрол (симптом — «20» вместо подписи вкладки «Лист заказа»).

| Поле | Якорь поля (dx, dy) | Якорь ед. изм. (dx, dy) | Единица / Значение |
| --- | --- | --- | --- |
| Адрес объекта | (256, 119) | — | строка, пишется с проверкой чтением |
| № заказа | (336, 99) | — | заполняется CCalc при сохранении |
| Стоимость | (392, 461) | — | Изделие с доп. элементами |
| Скидка №1, % | (317, 478) | — | 20% |
| Стоимость со скидкой | (392, 497) | — | 80% от стоимости |
| Демонтаж | (317, 514) | (260, 514) | `1м.пер.` / 100 ₽/м.п. |
| Монтаж | (317, 531) | (260, 531) | `1м.кв.` / 2365 ₽/м² |

Комбобоксы единиц измерения (`TComboBox`, список `['фикс.', '1м.кв.', '%', '1м.пер.']`) переключаются через `CB_SETCURSEL` + `CBN_SELCHANGE`:
- Для **демонтажа** обязательно выставляется `1м.пер.` (пункт 4, индекс 3), иначе при значении `%` ставка `100` рассчитывается как 100% от стоимости заказа!
- Для **монтажа** выставляется `1м.кв.` (пункт 2, индекс 1).

Запись значения: клик по центру поля → `WM_SETFOCUS` + `EM_SETSEL` +
`WM_CLEAR` + `WM_CHAR` → `Tab` (чтобы Delphi вызвал `OnExit`) → чтение поля
обратно. `WM_SETTEXT` до полей Delphi не доходит.

## Сохранение заказа

Заказ сохраняется по `Ctrl+S` при активном главном окне. После сохранения CCalc
заполняет поле «№ заказа» `(336, 99)` — оттуда номер и читается (в заголовке окна
номера нет). Если поле было не пустым, CCalc спрашивает «Вы уверены, что хотите
сохранить заказ под другим номером? В результате будет создана копия» — этот
диалог `#32770` подтверждается отдельно, иначе вместо номера остаётся пустая строка.

Живой прогон 15.11.2026: после сохранения поле «№ заказа» = `2330`.

## Передача заказа в A.R.C. Frame (реестр)

После каждого сохранения бот пишет `tools/pvc_bridge/orders/<номер>.json`:
адрес, сумма, габариты окна, подоконник, отлив, сетка, время сохранения (`register_order`).
Приложение читает этот реестр через `PvcAutoCalcService.LoadOrdersFromCcalcRegistry()`
и кнопка «Из CCalc» в панели «Заказы» создаёт обычный заказ A.R.C. Frame:

- адрес → `ClientAddress`;
- номер и сумма → доп. КП (`AdditionalKps`);
- `mosquito_net` → строка «Anwis» (режим размера «Профипласт», чтобы 445×1235 не пересчитывались в 478×1280), `flashing` → строка «Отлив»;
- адрес по умолчанию — «Димитрова 45/46»;
- `Id` заказа = GUID от «ccalc:<номер>» → повторный импорт обновляет тот же заказ.

Заказы, созданные только в CCalc без прогона бота, в реестр не попадают —
номер берётся из поля «№ заказа» после сохранения.

## Чтение данных без RPA

Контейнер `.ZKZ` (и те же блобы в `ccalc.mdb`) разобран на уровне заголовка —
`tools/pvc_bridge/zkz_parser.py`, подробности и границы применимости:
`agents/docs/CCALC_ZKZ_FORMAT.md`. Тело записи обфусцировано, поэтому
содержимое заказа по-прежнему снимается через RPA.

## Диалоги

- `TWHDialog`, `TStvorParDlg` — рабочие диалоги параметров, их нельзя закрывать «вслепую».
- `TDobElemDlg` (доп. элементы), `TListElemDlg`, `TDobElemEditDlg` — формы, которые остаются в памяти; `dismiss_all_blocking_dialogs` закрывает зависшие.
- Кнопки `TaskDialog` не нажимаются `BM_CLICK` — нужен реальный клик мышью по центру кнопки (`_real_click`).

## Известные ограничения

- Снятие москитной сетки: `TStvorParDlg` не открывается, сетка остаётся в расчёте
  (`net_removed: false`).
- Анкерные пластины и подоконник: поддержаны через `TDobElemDlg` с предварительным выбором строки конструкции `(62, 102)`.
  Проверено живьём 13.11.2026: 10 пластин + подоконник ПВХ 350×1350, стоимость 18 262 → 18 493 ₽, все шаги `--build` зелёные.
- Зависшие `TDobElemDlg`/`TListElemDlg`/`TDobElemEditDlg` блокируют главное окно: меню «Заказ» не открывается, и прогон падает уже на создании заказа. Перед стартом `--build` они закрываются автоматически (`_close_stale_dialogs`).
- То же делает полноэкранное окно «Печать» (`TShowPrint`): главное окно `TForm1` становится `IsWindowEnabled == 0`, и меню «Заказ» не открывается. `_close_stale_dialogs` закрывает и его.
- Перед прогоном обязательно `activate_window()`: клики уходят в активное окно, и без фокуса CCalc прогон падает на первом же меню (симптом — «меню «Заказ» не открылось»).
