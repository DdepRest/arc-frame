Этот файл хранит подробные технические хроники и историю рефакторингов прошлых версий программы (v3.40.0 — v3.54.3), перенесённые из активного [`CURRENT_STATE.md`](../CURRENT_STATE.md) по правилу **Rolling Window Policy** (лимит 5–10 версий в активном файле).

Агентам при решении текущих задач читать этот архив **НЕ ТРЕБУЕТСЯ**. Актуальное состояние системы описано в [`CURRENT_STATE.md`](../CURRENT_STATE.md).

## Исторические записи: v3.54.0 — v3.54.3

- **Аудит deadlock-класса «фон ↔ UI» закрыт обеими половинами + фикс мёртвого VC++-тоста (v3.54.1):** (1) фон→UI — все блокирующие `Dispatcher.Invoke` безопасны (`OnUpdateDetected` — по инварианту события fire всегда на UI-потоке → инлайн; `FixedDocumentBuilder` — dispatcher вызывающей нити; AI-стриминг `wait:true` — все `SendMessageAsync` через await); (2) UI→фон — в продакшене ноль блокирующих идиом (`.Wait()`/`GetAwaiter().GetResult()`/`SynchronizationContext.Send`/`WaitOne`/`Task.WaitAll`/`Thread.Join` отсутствуют; оба `.Result` — post-await чтения завершённых тасков; три `Thread.Sleep` ждут внешний мир — AV/файлы/другой процесс, цикл не замыкается). Реальный баг всплыл и исправлен: `NotifyIfMissingOnPortable` из `Task.Run` звал `ShowToast` напрямую → VerifyAccess бросал внутрь catch сервиса → тост «Скачать VC++» никогда не показывался портабельным пользователям; фикс choke-point — `ToastService.DeferToUiThread` (фоновый вызов → `BeginInvoke` на dispatcher владельца, UI-вызов инлайн; naive-фикс блокирующим Invoke создал бы класс deadlock v3.54.1). Харденинги: XML-инвариант `UpdateService.UpdateDetected` («fire всегда на UI-потоке; новый фоновый fire-site запрещён — marshal'ить сам fire») и shutdown-guard в `InvokeOnUi` AI-стриминга (`HasShutdownStarted` + exception filter). Страж — `DependencyCheckerServiceTests.NotifyIfMissingOnPortable_FromBackgroundThread_QueuesToastOnUiThread`. Разбор и правило — GOTCHAS §45. Сборка 0/0, полный прогон 2411/2411.
- **Автопин тестов журнала обновлений (v3.54.1):** ритуальные лок-версии `UpdateLogTests` удалены — оба теста (`AllNewestFirst_FirstItemIsNewest`, `GetChangesSince_LatestVersion_ReturnsEmpty`) сверяются с `UpdateService.CurrentVersion` (internal, резолвится из `<Version>` csproj через `VersionResolver`), как и требует запрет на brittle-пины в RELEASE_PROCESS. При bump ритуал «не забудь пин» больше не существует: тест падает только если запись новой версии не добавлена в `update-log.json` или противоречит csproj (сообщение об ошибке говорит, что именно сделать). История ловушки: 3.53.2 ушла в тег с пином на 3.53.1.
- **Пеноплекс (откос): 450 → 500 ₽/лист (v3.54.0):** дефолт обновлён в `DefaultPrices` (PriceService.cs) + Migration 7 в `ApplyMigrations` (поднимает ТОЛЬКО точный legacy-дефолт 450, пользовательские цены не трогает — правило Migration 6), fallback-дефолты `SlopeCalculatorService.Calculate/UpdateInPlace`, `SlopeOverlayCoordinator.LoadSlopePrices`, `SlopePanelControl.Prices`, эталонный `prices.json` в корне. Тест: `LoadPrices_Migration7_BumpsPenoplexDefault450To500`. Целевые прогоны 392/392 (PriceService/Slope/OrderItem/SlopePanel), полный — за CI.

## Archived on 2026-10-29

- **Детерминизм полного прогона тестов (Unreleased):**
  1. *Root cause «флакающей простыни»:* кисти темы — `DispatcherObject`/`Freezable`, владелец — поток, прочитавший первым. Не-STA тест (`ManualChecklistTests.Check1_ToggleTheme…`) применял тему на нити xUnit и пересоздавал ~60 кистей там; следующие 10–30 STA-тестов падали в `StyleHelper.SealIfSealable` (`VerifyAccess`), а виновник оставался зелёным.
  2. *Фикс:* `ThemeService.ApplyTheme`/`ToggleTheme` маршалят на `Application.Current.Dispatcher` (`Invoke`, порядок «флаг → кисти → `ThemeChanged`» атомарен; мёртвый dispatcher — тихий выход без касания ресурсов).
  3. *Самовосстановление:* `TestAppThemes.HasThemedApplication` при чужом владельце `Surface` пересобирает приложение на воркере; `THIEF-DETECTED`/`THIEF-KEYS` в `sta-diag.log` называют вора.
  4. *Тестовый кеш:* `AnwisContextMenuBuilderTests.MenuStyle` — `[ThreadStatic]` (общий `static readonly Style` переживал замену STA-воркера и валил весь класс).
  5. *Проверка:* 3 полных прогона (2651 тест) — идентичный результат 2645/6; 6 падений — долг сметы `DesignTokenGuardTests` (AI-разметка), не связан с правкой.

- **Косметический проход по аудиту интерфейса (v3.56, 11 дефектов):**
  1. *Превью быстрого ввода:* при пустых размерах чип показывает ставку (`1 800,00 руб/м²`) вместо вырожденной формулы «× 1 = 0,00 руб»; с размерами — обычная формула площади (`QuickAddControl.Preview.cs`, `IsAreaPriced`).
  2. *Сайдбар «Заказчик»:* `VerticalScrollBarVisibility=Auto` (скрытый скролл делал нижнюю карточку «обрезанной») и `ResetScroll()` при открытии оверлея — панель больше не открывается на середине.
  3. *Предпросмотр печати:* кнопка вписывания осталась действием «Вписать», процент ушёл в подсказку и появляется только после реального замера вьюпорта (`_fitZoomMeasured`) — рядом с настоящим `100%` больше нет двух одинаковых чисел.
  4. *Диалоги:* крестик `32×32` вместо `40×40` в шапке высотой 32 (пять окон) — больше не выступает за рамку.
  5. *Таблицы:* стили-шапки `LeftColumnHeader` / `RightColumnHeader` (только выравнивание, без литеральных паддингов) в «Расчёте», «Ценах» и «Заказах»; служебные колонки остались центрированными (`docs/specs/design-system-v3.53.md §5е`).
  6. *Мелочи консистентности:* «Глубина, мм» в калькуляторе откосов, плейсхолдер поиска и чип-бейдж `prices.json` в справочнике цен, убран дубль заголовка «ЗАКАЗЫ» (чип показывает «Найдено: X из Y» только при фильтре), подсказка `Ctrl+Z` в карточке «ИТОГО» живёт по состоянию стека отмены.
  7. *Страж:* `CosmeticFixesUiTests` (10 кейсов) рендерит реальные контролы на словарях темы, а не читает XAML регулярками.
  8. *Кадры не зависят от рабочих данных (2026-10-22):* хранилище заказов тоже подменяется фикстурой (`.tools/fixtures/orders`, три заказа 2-59/2-60/2-61) с возвратом байт-в-байт в `finally`; прерванный прогон больше не оставляет подмену — старт восстанавливает остатки `uiverify-orders-*`/`uiverify-profile-*` и откладывает всё, что появилось после аварии. Базлайны пересняты на фикстуре; `-Verify` — 17/17 в обеих темах.
  9. *Покадровая сверка (2026-10-22):* базлайны перезаписаны прогонами `uiverify` dark+light (по 17 кадров), обе темы проходят `-Verify` 17/17, `verify-pixels` — все токены в допуске. По дороге закрыты две неремонтоспособности кадра: плашка «Заказы • N заказов» считалась по отфильтрованному `OrdersGrid.Items` и исчезала при поиске без совпадений (теперь — `OrdersHistoryControl.TotalOrders`), а `Select-ComboItem` в харнессе мог тихо не выбрать пункт (теперь выбор доказывается по `SelectionPattern`, иначе сцена падает) — GOTCHAS §54.
