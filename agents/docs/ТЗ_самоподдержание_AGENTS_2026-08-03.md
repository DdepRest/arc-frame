# ТЗ — Самоподдержание системы AGENTS.md / agents/docs

**Дата:** 2026-08-03
**Статус:** согласовано владельцем (интервью insviewer, вопросы 1–7)
**Версия проекта на момент ТЗ:** v3.47.3

---

## 1. Контекст и цели

Система multi-agent контроля (`AGENTS.md` → `MULTI_AGENT_ARC_CALC_CONTROL.md`) существует, но:

1. **Причина №1 — верификация:** владелец хочет убедиться, что система реально помогает агентам (экономит токены, направляет к нужным файлам), а не просто существует.
2. **Причина №2 — самоподдержание:** в системе не прописана обязанность ИИ держать её в актуальности. Агент может разбить файл на части, переименовать класс, добавить сервис — и документация (SYMBOL_INDEX, INTENTS, MODULES, routing) остаётся устаревшей. Устаревшая документация **активно вводит в заблуждение** — хуже отсутствующей.

**Диагноз (подтверждён фактами 2026-08-03):** `validate-docs.ps1` уже ловит рассинхрон: 1 issue (версия CURRENT_STATE 3.47.2 ≠ csproj 3.47.3) + 20 warnings (устаревшие даты в 10 файлах, в т.ч. CHEATSHEET «v3.42.0» при фактической v3.47.3). То есть механизм проверки работает — но правила «агент обязан обновлять docs» в системе нет, и протухание накапливается.

## 2. Функциональные требования

### 2.1 Обязанность самоподдержания (главное)

Прописать в системе (канонический файл + CHEATSHEET + AGENTS.md) явную обязанность: **ИИ может и должен обновлять систему AGENTS.md/agents/docs, если данные неактуальны**, и **должен фиксировать структурные изменения кода в документации в том же цикле работы**.

Ситуации, требующие обновления документации (согласованы: все важны):

| # | Ситуация | Что должно обновляться |
|---|---|---|
| А | Разбивка большого файла на части | SYMBOL_INDEX, INTENTS, MODULES, DOCUMENTATION_MATRIX, CURRENT_STATE, CHANGELOG |
| Б | Переименование/перемещение файлов и классов | SYMBOL_INDEX, INTENTS, MODULES, DOCUMENTATION_MATRIX |
| В | Появление нового класса/сервиса/модуля | SYMBOL_INDEX (через gensymbols.ps1), INTENTS, MODULES |
| Г | Изменение сигнатур методов/свойств (упомянутых в SYMBOL_INDEX) | SYMBOL_INDEX (через gensymbols.ps1) |
| Д | Изменение бизнес-логики (формулы, цены, монтаж) | CALCULATION_LOGIC, GOTCHAS, CALCULATION_TEST_CASES + critical domain ритуал (§3) |
| Е | Изменение процессов (релиз, автообновление) | RELEASE_PROCESS, AUTO_UPDATE |
| Ж | Изменение самой системы документации (правила, routing) | MULTI_AGENT_ARC_CALC_CONTROL, CHEATSHEET, AGENTS.md, CURRENT_STATE |

### 2.2 Механизмы (согласованы А+Б+В+Г)

- **А. Автоматические проверки** — усилить `validate-docs.ps1`: мягкая проверка устаревания версии в `Last verified` файлов agents/docs против csproj.
- **Б. Ритуал по шагам** — в цикле работы агента (фаза Document) явный шаг: «структурные изменения → gensymbols.ps1 → обнови INTENTS/MODULES/matrix → validate-docs.ps1».
- **В. Метрики** — в шаблон финального отчёта добавить строку о количестве шагов/токенов, сэкономленных системой (например, «класс найден по SYMBOL_INDEX за 1 чтение»).
- **Г. Ревью** — после изменений системы agents/docs прогонять code-reviewer.

### 2.3 Уровень жёсткости

**Мягкий:** проверки предупреждают (warnings), но не блокируют коммит/завершение. Агент обязан устранить рассинхрон до финального отчёта, но без жёстких git-gate'ов.

## 3. Объём изменений

Можно изменять всю систему: `AGENTS.md`, все `agents/docs/*.md`, скрипты (`validate-docs.ps1`, `arc-check.ps1`, `what-to-update.ps1`, `gensymbols.ps1`, `render-matrix.ps1`), `documentation-matrix.json`, `CHANGELOG.md`. Код приложения (.cs/.xaml) **не** трогаем. Допустимо сжатие/объединение секций при устаревании данных.

## 4. Критерии приёмки

1. В каноническом файле и CHEATSHEET явно прописана обязанность самоподдержания (ситуации А–Ж + ритуал).
2. `AGENTS.md` (wrapper) содержит правило: при изменении структуры agents/docs wrapper обновляется.
3. `validate-docs.ps1` содержит новую мягкую проверку устаревания версии; после правок — 0 issues (допустимы warnings по мягким проверкам, не блокирующие).
4. `INTENTS.md`, `DOCUMENTATION_MATRIX.md` (через JSON), `CURRENT_STATE.md`, `CHANGELOG.md` обновлены.
5. Тест-драйв: SYMBOL_INDEX находит целевой класс за 1 поисковый шаг; зафиксирован baseline и результат.
6. Ревью изменений проведено (code-reviewer).

## 5. Риски

- Изменение канонического файла — зона «Ж» (система сама себя правит) → после правки обязательно `validate-docs.ps1`.
- Новая мягкая проверка может дать много warnings на старых файлах → это ожидаемо (soft level), предупреждения служат сигналом для будущих агентов.
