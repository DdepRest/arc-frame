3. In `MosquitoNetCalculator/Services/OrderStorageService.cs`:

### 1.2 Implemented Changes
1. `MosquitoNetCalculator/Models/OrderData.cs`:
   Added `[System.Text.Json.Serialization.JsonIgnore]` property:
   ```csharp
   [System.Text.Json.Serialization.JsonIgnore]
   public bool IsEmptyDummy => (Items == null || Items.Count == 0) && Math.Abs(TotalAmount) < 0.001;
   ```
2. `MosquitoNetCalculator/Services/OrderStorageService.cs`:
   - Updated `SoftDeleteOrder(string orderId)`: Before moving to trash, deserializes order from `sourcePath`. If `order != null && order.IsEmptyDummy`, it deletes the file permanently via `File.Delete(sourcePath)`, clears `_cachedOrders = null`, and returns immediately so it NEVER enters `TrashDir`.
   - Added public static method `CleanEmptyTrashOrders(string? trashDir = null)`:
     Scans target directory (defaulting to `TrashDir`), deserializes each `.json` file, and permanently deletes any file where `order == null || order.IsEmptyDummy`.
   - Called `CleanEmptyTrashOrders()` in the `OrderStorageService` constructor and in `LoadTrashOrders()`.
3. `MosquitoNetCalculator.Tests/Services/OrderStorageServiceTests.cs`:
   - Updated `DeleteOrder_MovesToTestTrashDir_AndDoesNotPolluteProductionTrash` to use a non-dummy order (`TotalAmount = 2500, Items = 1 item`) so it exercises the trash-move behavior.
   - Added unit test `SoftDeleteOrder_EmptyDummyOrder_PermanentlyDeletesAndDoesNotEnterTrash`: verifies that soft-deleting an empty dummy order deletes it from `_ordersDir` and leaves `_trashDir` empty.
   - Added unit test `CleanEmptyTrashOrders_RemovesOnlyDummyOrders`: verifies that dummy orders and corrupted files are removed while orders with items/amounts remain.
   - Added unit test `CleanEmptyTrashOrders_ProductionTrashFolder_PurgedOfDummyOrders`: cleans and asserts zero files in `%APPDATA%\MosquitoNetCalculator\orders_trash`.
   - Added unit test `OrderData_IsEmptyDummy_EvaluatesCorrectly`: tests boundary cases for `IsEmptyDummy`.

## 2. Logic Chain

1. **Premise 1**: Requirement R4 mandates that empty dummy orders (0 items and 0.00 ₽ sum) must never enter the trash directory on deletion/reset, and that existing dummy files in `%APPDATA%\MosquitoNetCalculator\orders_trash` must be purged.
2. **Premise 2**: In `OrderData.cs`, the definition `IsEmptyDummy => (Items == null || Items.Count == 0) && Math.Abs(TotalAmount) < 0.001` provides a single source of truth for identifying empty dummy orders. Marked with `[JsonIgnore]` per the codebase contract, no dead bytes are serialized to JSON.
3. **Premise 3**: In `OrderStorageService.SoftDeleteOrder`, deserializing the order from `sourcePath` before moving permits an inspection: if `order.IsEmptyDummy`, calling `File.Delete(sourcePath)` permanently eliminates the order from `OrdersDir` and aborts before creating or writing to `TrashDir`.
4. **Premise 4**: Implementing `CleanEmptyTrashOrders(string? trashDir = null)` and calling it during service construction and `LoadTrashOrders()` guarantees that any legacy or external dummy files are pruned whenever trash is accessed.
5. **Deduction**: All 14 existing dummy order files in `%APPDATA%\MosquitoNetCalculator\orders_trash` have been removed (verified count = 0), new dummy deletions bypass trash, and all 54 `OrderStorageServiceTests` pass cleanly.

## 3. Caveats

1. **Downstream Test Assertion in M2 Files**:
   During Milestone 2, assertions checking that deleted orders exist in `_trashDir` were added to:
   - `MosquitoNetCalculator.Tests/App/ManualChecklistTests.cs:345` (`Check5_Delete_Removes_From_List`)
   - `MosquitoNetCalculator.Tests/ViewModels/OrdersHistoryViewModelTests.cs:478` (`SaveAndDelete_Roundtrip`)
   In both of those tests, the test order was created as `new OrderData { ... }` with 0 items and 0.00 ₽ sum.
   Because Milestone 3 genuinely and correctly prevents empty dummy orders from entering trash (permanently deleting them instead), asserting `Assert.True(File.Exists(Path.Combine(_trashDir, ...)))` fails for those two dummy orders.
   Per strict exclusive write ownership constraints, Milestone 3 worker did not modify those two test files. To resolve them in full test suite runs: either those test orders should specify `TotalAmount = 1000` / `Items` (to test moving a real order to trash), or their assertions should be updated to `Assert.False(File.Exists(...))`.
